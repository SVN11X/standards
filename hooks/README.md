# hooks

Claude Code hooks published with the skills plugin. Hooks are scripts that Claude Code runs at fixed moments, so these rules hold even when the agent forgets them.

- `guard.py` (before every shell command): asks the owner before merging (or, when the owner allowed merges with `orchestrate.py consent --merge when-green`, sends the agent to `scripts/merge_when_green.py`, which merges only after every check passed), deploying, force pushing, rewriting history, mass deletions, publishing packages, changing secrets, pulling or deleting local models, global installs, or changing which folders may use remote models. Deleting a `delegate/<run id>` branch with a run record in `~/.standards/runs` does not ask: it is scratch the standard made for one delegation. A recursive deletion inside a temporary folder (the session's scratchpad, the system temp folder, a delegation's worktree) does not ask either, when every target resolves to a path inside it. Blocks `git commit` while the standard check of the repository fails.
- `secret_scan.py` (after every file write): stops the agent when the file now contains a credential, so it moves it to an environment variable.
- `session_probe.py` (when a session starts in a repository with `.standard.yml` or in the standard's own repository): says which executors this machine has and how to route and delegate. It only looks, in about a second.
- `route_prompt.py` (on every prompt): adds the router's decision to a work, review, setup or publish request inside a git repository: the folder, the recipe, the provider of each capability, the verification and the permission it needs. A question gets nothing and a prompt is never blocked. "Continúa", "sigue" or "retoma" also starts one pass of `scripts/supervisor.py` in the background, which resumes only plans already started. `STANDARDS_NO_SUPERVISOR=1` turns that off. See `docs/011-request-router.md`.
- `reinject.py` (after a compaction): puts the key rules of `AGENTS.md` and the plan status back in context.
- `shift_notice.py` (after every file read or write): remembers which files each session read in `~/.standards/shift.db`, and tells a session when another one changed such a file afterwards, in the same working tree or in another worktree of the repository. `STANDARDS_SHIFT_NOTICE=0` turns it off. After the swarm of jcode.
- `cache_notice.py` (before a prompt and when the agent stops): from the usage the provider reports in the local transcript, says when a prompt starts on a cold cache and names the likely reason of a cache miss. The cache lifetime comes from the transcript, one hour when recent answers wrote one hour entries, else 5 minutes, unless `STANDARDS_CACHE_TTL_MIN` sets it. Claude Code's own `<synthetic>` messages, such as a usage limit notice, are not counted as requests. After the KV cache monitor of jcode.
- `notify.py` (when Claude Code needs the owner): plays a short sound.
- `autopilot.py` (when the agent is about to stop): while `standard-autopilot` exists in the git folder (`git rev-parse --git-path standard-autopilot`, also in linked worktrees), keeps the session working through `docs/improvement-plan.md`. Delete the file to turn autopilot off.

## Known limits

- In Claude Desktop with Claude Code 2.1.326, a session that another session opens (the app's `start_session`) loads the plugin's skills but runs none of its hooks. There is no startup context and no router context, neither on its first message nor on messages from other sessions. Seen on 2026-11-18. That session left no task record in `~/.standards/router/tasks`, while `claude -p` in the same folder ran `session_probe.py` and `route_prompt.py`.
- Whether the tool hooks (`guard.py`, `secret_scan.py`, `shift_notice.py`) run there was not checked.
- A session the owner opens and types in runs the hooks.
- So a session that opens another one puts what the hooks would add into the brief: the router decision from `python scripts/router.py route "REQUEST" --cwd DIR`, and the rules of `AGENTS.md` that matter for the task.
