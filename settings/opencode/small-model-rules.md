## Limits for OpenCode

You run on a free or small model to save Claude usage. Claude Code plans, reviews and runs repo-improve. These lines narrow the ones above.

- Take only work you can finish and verify in one session: one item of `docs/improvement-plan.md`, a bug with a known cause, tests, docs, or the errors the check reports.
- Stop and say so in one line when a task needs a design decision, touches more than five files, changes a public interface or a data format, or is unclear. The owner moves it to Claude Code.
- In web work you may copy a pattern from `interaction-patterns.md` of the web-improve skill as it is written. You never invent visual direction, pick a sub-profile for a redesign or judge how a page looks. Stop on any design decision.
- A model that cannot read images does not review appearance. Its visual work counts only after the check and the Playwright screenshots pass.
- Do not use repo-improve or the deep mode of code-review here. They need Claude Code subagents and hooks.
- Never write `AGENTS.md`. It is generated by the standard's `agents` command.
- No hook runs here, so `/who-does-what` replaces the startup list: it prints who does each task type on this machine and why. A blocked task is reduced or goes to the owner, never to a paid model.
- No hook checks your work here. Run the check (README.md, section Standard) and the tests before every commit, and commit only when both pass.
- Work on a branch. Never push, merge, deploy or publish. The owner does that.
