## Writing

- [core] Use plain words. Explain a technical term briefly the first time it appears.
  - Good: "The pipeline is idempotent (running it twice gives the same result)."
  - Bad: "The pipeline leverages a robust idempotent paradigm."
- [core] Do not use em dashes or semicolons as separators. Use periods and commas.
  - Good: "The check failed. Fix the README and run it again."
  - Bad: "The check failed, so fix the README; then run it again."
- One idea per section or column.
  - Good: one heading per decision.
  - Bad: one paragraph that mixes the decision, its history and three side notes.
- Avoid math symbols such as the summation sign in explanations. Say it in words.
